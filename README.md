# GSPDOffline - Generalized Trace-Based Sync-Preserving Deadlock Prediction in Linear Time

## Description

This is a C++23 deadlock predictor that combines the works of https://dl.acm.org/doi/epdf/10.1145/3591291 found soundness and efficiency and https://dl.acm.org/doi/epdf/10.1145/3533767.3534377 for more deadlock coverage. It takes as inputs program traces and gives back log files with possible deadlock reports.

## Dependencies

- Python dependencies: pandas==3.0.3
- C++23 (no extra dependencies)
- CMake
- Java 21 (no extra dependencies)

## How to install and run

1. git clone https://github.com/lucan8/SUnhang.git
2. cmake --build build
3. python scripts/run.py

This will build necessary executables and will run the script with default settings.

## Directory structure

### Benchmarks

The `benchmarks` directory contains multiple subdirectories for each benchmark suite.

benchmarks
├── cond_var
├── generated
└── original

The benchmark suites are similar in structure. Here is how `benchmarks/cond_var` looks.

benchmarks/cond_var/
├── src
│   └── cond_var
├── tables
└── traces
    ├── bin
    │   ├── java_enc
    │   └── local_enc
    └── std

`tables` contains the resulted table after running the benchmark and the tex file used to generate it. The tex file will be generated by scripts, the pdf needs to be constructed by you(using overleaf or a latex compiler). The additional packages you will need are `booktabs` and `graphicx` (for overleaf add `\usepackage{booktabs}` and `\usepackage{graphicx}` in your preamble)

`traces` contains the traces in differnt formats. The ones used for running are the ones in bin, while the ones in std are used for visualization. `java_enc` is used by the predictor SPDOffline, while `local_enc` is used by our predictor.  

An additional `output` directory will appear for each benchmark suite after running, looking something like this:

benchmarks/cond_var/output/apache_42031_dlf/
├── SPDOffline
│   └── log.txt
└── SUnhang
    └── log.txt

Where `log.txt` contains information reported by the predictor, like the number of events, the deadlocks or runtime.

### Scripts

Note: For all the scripts you can run `python scripts/{script_name} -h` to get information about the available flags.  

`run.py` is the one you should use to reproduce the benchmarks. The default settings run all predictors on the `cond_var` benchmark suite for 10 iterations, compute the mean and save the results as a latex table.  

`conv_trace.py` is used to convert traces from a given format to another. The default settings convert from `java_enc` to `local_enc`.  

`compile_benchmarks.py` is used to construct the latex tables from the `log.txt` files of the predictors. The default beaviour constructs the table from the output of al available predictors.  

`settings.py` has stuff like `bench_suite` or `available_predictors` and A LOT of paths used throught the program. The only thing you can safely change here is the benchmark suite, though it would be advised to do so through the `--bs` flag when running the other scripts.  

`util.py` has helper functions.  

`help.py` has functions used by me to clean-up or print statistics. It is not used directly by the application, only for development.
